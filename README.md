# Golang Notes Microservices API

REST API приложение для управления заметками. Проект построен на базе микросервисной архитектуры.

## Технологический стек

| Компонент | Технология |
| :--- | :--- |
| **Язык** | Go 1.25.5+ |
| **HTTP-фреймворк** | Gin |
| **Базы данных** | PostgreSQL, MongoDB |
| **ORM** | GORM |
| **Кэш** | Redis |
| **API Gateway** | Nginx |
| **Логгер** | go.uber.org/zap |
| **Деплой** | Docker, Docker Compose |

## Архитектура

Бэкенд разделен на три независимых микросервиса. Каждый из них имеет собственную базу данных, изолированную инфраструктуру Docker Compose и общается с остальными через общую внутреннюю сеть Docker.

*   **Auth (Сервис авторизации):** Микросервис для управления авторизацией, выдачей токенов и хранения данных пользователя. Данные хранятся в реляционной базе данных PostgreSQL, а для взаимодействия с ней используется GORM.
*   **Notes (Сервис заметок):** Микросервис, предоставляющий CRUD операции для управления заметками. В качестве основного хранилища используется документоориентированная MongoDB. Для повышения производительности реализовано кэширование с помощью Redis (через паттерн Декоратор).
*   **Nginx (API Gateway):** Веб-сервер для объединения двух микросервисов. Он принимает все внешние запросы на 80-й порт и маршрутизирует их к нужным внутренним сервисам, скрывая внутреннюю логику и порты от клиента. Для быстрого конфигурирования и разворачивания используется Docker.

## Локальный запуск и деплой

### Предварительные требования
*   Docker и Docker Compose
*   Make
*   Go 1.25.5+ (для локального запуска вне контейнеров)

### Разворачивание через Docker

1. **Создание общей сети:**
   Чтобы изолированные контейнеры могли общаться друг с другом через Nginx, сначала создайте глобальную сеть:
   ```bash
   docker network create microservices-net
   ```

2. **Запуск микросервисов:**
   Соберите и поднимите приложения вместе с их базами данных:
   ```bash
   make auth-deploy
   make notes-deploy
   ```

3. **Запуск API Gateway:**
   ```bash
   make gateway-up
   ```

4. **Проверка статуса:**
   ```bash
   make ps
   ```

5. **Глобальное тестирование:**
   Запустите автоматизированный скрипт, который симулирует регистрацию, создание, обновление и удаление заметок напрямую через Gateway:
   ```bash
   make gateway-test
   ```

## API Документация

Все запросы проходят через единую точку входа `http://localhost/` (Nginx).

### Пользователи `/auth/`
| Метод | Путь | Описание |
| :--- | :--- | :--- |
| POST | `/auth/register` | Регистрация нового пользователя |
| POST | `/auth/login` | Вход и генерация Access/Refresh JWT токенов |
| POST | `/auth/refresh` | Обновление токенов через Refresh Token |
| GET | `/auth/user` | Получение информации о профиле |
| PATCH | `/auth/user` | Частичное обновление профиля |
| DELETE | `/auth/user` | Удаление аккаунта пользователя |

### Заметки `/notes/`
| Метод | Путь | Описание |
| :--- | :--- | :--- |
| POST | `/notes` | Создание новой заметки (валидация по JWT) |
| GET | `/notes` | Список всех заметок (результат кэшируется в Redis) |
| GET | `/notes/{id}` | Получение конкретной заметки по ID (кэшируется) |
| PATCH | `/notes/{id}` | Обновление заметки (автоматическая инвалидация кэша) |
| DELETE | `/notes/{id}` | Удаление заметки (очистка кэша списка и конкретного ID) |
